# 插件管理页（`/m/plugin-manager/`）

> 《Y.Stage3 手册》章节 · 面向管理员；面向开发者的管理面实现见[插件开发技术参考](./plugin-development.md)。

## 1. 它是什么

管理页本身也是一个插件（这是本项目"界面插件化"的示范），提供全部模块的可视化管理：**不修改代码、不重启服务**即可启停功能、编辑配置、热重载。

页面分三个标签：**前端插件**（页面 / 组件两组）、**后端插件**、**主题插件**（主题插件组视图）。列表显示与搜索命中插件的中文名（清单条目 `label`，如「音乐播放器」「音乐库（扫描 / 上传 / 回收）」），未声明时回退插件 id。

## 2. 操作与生效时机

| 操作 | 效果 |
|------|------|
| 启用/停用后端插件 | **即时生效**：其路由与页面物理 404（请求排空保证在途请求安全完成），SQLite 数据保留 |
| 编辑 config | 写入清单并热重装，即时生效 |
| 热重载 | 改盘上的插件文件后无需重启即生效 |
| 前端插件开关 | 落盘后**刷新页面**生效 |
| 主题组「启用整组 / 禁用整组」 | 对组内成员**串行**逐个前端开关（每次操作都整包写盘清单，`groupBusy` 锁防并发写）；个别失败会在状态行点名未生效条目；刷新页面生效 |
| 组卡「设为系统主题」 | `PUT /api/theme/active`（主题 id 经格式校验），各页面刷新后生效 |

## 3. 语义细节

- **停用不丢数据**：SQLite 数据完整保留，重新启用即恢复
- **请求排空**：热重载瞬间，正在保存的比赛进度会安全完成；新请求会短暂收到 503（自动重试即可），比赛进行中热重载正在使用的模块属于低风险操作，但仍建议避开
- **便携包内**：所有改动写入 `plugins/` 目录下的真实清单文件，**重启后保持**
- **清单即事实**：手动编辑 `plugins/plugins.json` / `front.json`（或 dev 模式的 `server/plugins.json` / `web/front.json`）与在页面上操作等效

## 4. 「主题插件」标签（主题插件组视图）

一个主题 = **一个插件组**：主题核心（`component-theme-<组id>`）+ 组件成员（id 以 `component-<组id>-` 开头）。每个主题一张可折叠组卡，另有「默认主题」虚拟组卡恒排最前（代表无插件条目的原生皮肤，停用全部主题插件即回到默认外观）。

- **组卡头部**：组显示名（核心条目 `group.name`，缺省回退组 id）、「已启用 x / 共 y」、当前主题徽标（读 `GET /api/theme/active`）；控件 = 设为系统主题（当前主题组该按钮禁用）/ 启用整组 / 禁用整组 / 展开收起
- **成员行**：带「主题核心」/「组件成员」标签，可逐个启用 / 禁用
- **成员归属规则**：命名约定（成员 id 以 `component-<组id>-` 开头，**最长前缀优先**，防嵌套组误归属）∪ 核心条目 `group.members` 显式 id 数组（适配命名约定覆盖不到的成员；清单中不存在的 id 跳过）
- **搜索与筛选**：搜索命中中文名 / id / 插件名；状态筛选 chips 只作用于成员行，组卡头部不受影响
- 标签徽标 = 主题条目数（核心 + 成员）；页脚计「主题 N 组」
- 主题预览与切换 → 组卡上的「管理」链接（`/m/theme-manager/`）

自建主题插件：新建 `modules/component-theme-<id>/` 组件插件并登记 `web/front.json`（条目加 `label` 中文名与 `group` 组声明），本页与主题管理页都会自动出现。

## 5. 常见操作

- 某个赛制页 404？→ 到管理页确认该插件是否被停用，重新启用即可
- 改了某插件的代码？→ 管理页对该插件"重载"，无需重启
- 想临时隐藏某个功能？→ 停用它，数据不丢，随时恢复
- 想换界面风格 / 整组启停主题？→「主题插件」标签，见上节
